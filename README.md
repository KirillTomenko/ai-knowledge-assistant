# AI Knowledge Assistant

RAG-ассистент для сотрудников, которые ищут правила работы в инструкциях компании. Вместо ручного просмотра файлов сотрудник задаёт вопрос и получает ответ с названием документа и фрагментом для проверки. Это портфолио-проект AI Automation Developer / Python Backend Developer, а не подтверждённое клиентское внедрение.

## Демонстрация за 30 секунд

Выбран один сценарий: правила удалённой работы вымышленной компании «Север». Два небольших [учебных документа](demo/documents) не содержат реальных корпоративных данных.

**Вопрос:** «Сколько дней в неделю можно работать удалённо и когда нужно согласовать дни?»

**Ожидаемое содержание ответа по учебному регламенту:** до двух дней в неделю, согласование с руководителем до 16:00 предыдущего рабочего дня. Подтверждение: [sever_remote_work.txt, раздел 1](demo/documents/sever_remote_work.txt). Это эталон для проверки, **не фактический ответ модели**.

В API результат содержит `answer` и `sources` с полями `source`, `page`, `excerpt`. Для TXT `page=1` — техническая метка всего файла, а не настоящая нумерация страниц. Открыть оригинал нужно вручную: ссылки на скачивание API не создаёт.

**Статус демонстрации:** локальный отчёт — [demo/results.json](demo/results.json), пояснения — [demo/VERIFICATION.md](demo/VERIFICATION.md). Ответы модели пока не получены: не восстановлены ключи OpenAI/ProxyAPI и Supabase и пароль администратора. Полный прогон приложения с OpenAI/ProxyAPI и живой Supabase не выполнен; Telegram не проверен. Прямой вопрос, перефразировка и вопрос без ответа подготовлены; их успешное прохождение не заявляется.

**Проверка человеком обязательна:** найденный фрагмент нужно сопоставить с ответом. `sources` перечисляет результаты поиска, а не доказанные моделью цитаты. `has_context=true` означает лишь наличие найденных чанков. Отказ при отсутствии информации задан промптом, но качество отказа на непустой базе ещё не проверено.

## Что реализовано в коде

- FastAPI: загрузка документов, фоновая индексация, статусы, список и удаление документов, HTTP Basic Auth.
- Парсер TXT, текстовых PDF и DOCX; разбиение на чанки; embeddings через OpenAI-совместимый API; векторное хранение ChromaDB.
- `POST /api/v1/ask`: поиск, сборка контекста, вызов LLM, ответ и извлечённые источники.
- Telegram-обработчики вопросов, истории, заметок и статистики. В этой итерации проверяется API-сценарий; Telegram end-to-end не проверен.
- `/health`: ChromaDB и LLM. Доступность Supabase эта ручка **не проверяет**; HTTP 200 сам по себе не означает готовность RAG.

Не заявляются: гарантированная точность, измеренная экономия времени, production-ready, OCR сканов, проверенный лимит 500 страниц. Расширение DOC принимается API, но передаётся парсеру DOCX; бинарный DOC не входит в проверенный сценарий.

## Локальный запуск (Windows PowerShell)

Нужны Python **3.12**, Docker с Linux engine и тестовый проект Supabase. Старые прямые зависимости согласованы минимальными изменениями версий; обновление всего стека в эту итерацию не входит.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements/api.txt -r requirements/bot.txt -r requirements/test.txt
# Только если .env ещё не существует:
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

В `.env` восстановите `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_KEY`, задайте `ADMIN_PASSWORD`. Убедитесь, что `OPENAI_BASE_URL` соответствует поставщику ключа и доступны модели `LLM_MODEL` и `EMBEDDING_MODEL`.

Для выбранного API-сценария:

```dotenv
CHROMA_HOST=127.0.0.1
CHROMA_PORT=8001
CHROMA_COLLECTION_NAME=demo_sever_2026
API_HOST=127.0.0.1
API_PORT=8010
HTTP_PROXY=
HTTPS_PROXY=
```

Прокси заполняйте только при необходимости реальным локальным адресом. `host.docker.internal` из шаблона предназначен для контейнеров. `TELEGRAM_PROXY_URL` код не читает. `TELEGRAM_BOT_TOKEN` нужен для бота; в API-демо строка может оставаться пустой. `DATABASE_URL` и `API_SECRET_KEY` есть в настройках, но текущая цепочка их не использует.

В **тестовом** Supabase выполните [sql/schema.sql](sql/schema.sql) один раз. Используйте ключ с доступом к `documents`, `dialog_history`, `user_notes`; проверьте права/RLS в своём проекте. Миграций Alembic в репозитории нет. Повторный запуск SQL без проверки не нужен: триггер и индексы не объявлены идемпотентно.

```powershell
docker compose up -d chromadb
.\.venv\Scripts\python.exe -m uvicorn src.api.main:app --host 127.0.0.1 --port 8010
```

Swagger: **http://127.0.0.1:8010/docs**. Порт 8010 выбран, потому что 8000 на машине подготовки уже занят другим проектом. ChromaDB: `127.0.0.1:8001`. После изменения `.env` перезапустите API.

В другом терминале из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m demo.run
# После восстановления настроек: загрузка двух учебных файлов и три реальных запроса.
# Использует платные embeddings/LLM и записывает учебные документы в тестовую БД.
.\.venv\Scripts\python.exe -m demo.run --live
```

Если настроек нет, отчёт сохраняет `actual_answer: null`, пустой список фактических источников и причину блокировки. Это не отказ модели отвечать на вопрос.

Для Telegram после отдельной настройки токена: `python -m src.bot.main`. Полный Compose: `docker compose up -d --build`; API там использует порт **8000**, который должен быть свободен. Dockerfiles исправлены по обнаруженным блокерам, но полная сборка API/бота и Telegram в этой итерации не проверялись.

## Архитектура и стек

```text
API upload → Supabase: pending → DocumentParser → chunks
           → OpenAI embeddings → ChromaDB → Supabase: done/error
API ask → RAGService → поиск ChromaDB → контекст → LLM → answer + sources
Telegram → отдельный legacy RAGRetriever → история/заметки в Supabase
```

API использует `src/services/rag_service.py`, Telegram пока использует `src/rag/retriever.py`; это разные реализации, их эквивалентность не проверена. Оперативная память диалога в API `/ask` не передаётся, хотя сервис её поддерживает.

Python 3.12 · FastAPI 0.115.5 · aiogram 3.14 · LangChain 0.3 · ChromaDB 0.5.20 · OpenAI SDK · Supabase. Модели по шаблону: `gpt-4o`, `text-embedding-3-small`. Их доступность нужно подтвердить у своего провайдера.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Статус ChromaDB и LLM, без авторизации |
| POST | `/api/v1/documents/upload` | Загрузка, возвращает ID и статус |
| GET | `/api/v1/documents/{id}/status` | Ожидание `done` или `error` |
| GET | `/api/v1/documents/` | Список документов |
| DELETE | `/api/v1/documents/{id}` | Удаление документа и векторов |
| GET | `/api/v1/collections/` | Список коллекций |
| POST | `/api/v1/ask` | Вопрос и структурированные источники |

Все `/api/v1/*` защищены HTTP Basic Auth. Для показанного сценария используйте отдельную коллекцию и тестовую Supabase: изоляции организаций/пользователей в API не реализовано.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest
```

В тестах внешние API и хранилища подменяются моками. Регрессионный тест демонстрации проходит через HTTP upload и настоящий TXT-парсер и проверяет, что источник сохранил имя файла, а выдержка находится в оригинале. Это проверка обработки источника, а не оценка качества embeddings или LLM. Фактические результаты и оставшиеся блокеры записаны в [отчёте проверки](demo/VERIFICATION.md).
