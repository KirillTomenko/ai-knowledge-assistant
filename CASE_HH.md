# AI Knowledge Assistant — Кейс для резюме (HH.ru)

---

## 🔷 Проект: RAG-система для корпоративного поиска по документам

**GitHub:** https://github.com/KirillTomenko/ai-knowledge-assistant  
**Стек:** Python 3.12, FastAPI, aiogram 3.x, LangChain, ChromaDB, GPT-4o, Supabase, Docker

---

### 📌 Проблема / Задача

Корпоративные сотрудники тратят значительное время на поиск информации в регламентах, инструкциях и внутренних документах (PDF, DOCX). Стандартный поиск по ключевым словам не понимает смысл вопроса и не учитывает контекст.

**Задача:** Создать систему, которая позволяет сотруднику задать вопрос на естественном языке и получить точный ответ со ссылкой на источник — через Telegram, без необходимости самостоятельно искать нужный документ.

---

### ✅ Решение

Разработал производственный RAG-ассистент (Retrieval-Augmented Generation) по схеме:

1. **Загрузка и индексация** (FastAPI + BackgroundTasks): администратор загружает PDF/DOCX/TXT через REST API. Документ автоматически парсится, разбивается на смысловые чанки (`RecursiveCharacterTextSplitter`, 1000 символов, overlap 200) и индексируется в ChromaDB через `text-embedding-3-small`.

2. **Поиск и генерация** (LangChain RetrievalQA): при запросе пользователя система векторным поиском находит Top-5 релевантных фрагментов, формирует промпт с контекстом и получает ответ от GPT-4o с указанием источника.

3. **Telegram-интерфейс** (aiogram 3.x): пользователь общается в привычном мессенджере. История сохраняется в Supabase, поддерживается контекст последних сообщений.

### 🔴 Технические сложности и решения

**1. Обработка больших документов (до 500 страниц)**

*Проблема:* Синхронная индексация PDF на 500 страниц с генерацией embeddings занимает 2-5 минут и блокирует API.

*Решение:* Индексация вынесена в `FastAPI BackgroundTasks`. Статус задачи (`PENDING → PROCESSING → DONE → ERROR`) хранится в Supabase и доступен через polling-эндпоинт. Клиент может отслеживать прогресс без блокировки.

**2. Сетевые ограничения — работа через прокси из России**

*Проблема:* Прямой доступ к OpenAI API и Telegram заблокирован. Приложение работает в Docker-контейнерах.

*Решение:* 
- OpenAI-запросы идут через ProxyAPI (`https://api.proxyapi.ru/openai/v1`) с передачей кастомного `httpx.AsyncClient(proxy=...)` в SDK.
- Telegram Bot подключается через локальный SOCKS5 (Karing, порт 3067) с использованием `AiohttpSession(connector=ProxyConnector.from_url(...))` из `aiohttp-socks`.
- В Docker адрес хоста: `host.docker.internal:3067`.

**3. Потеря контекста при RAG**

*Проблема:* Ответ GPT не учитывает предыдущие сообщения диалога.

*Решение:* Последние N сообщений (по умолчанию 5) загружаются из Supabase и добавляются в промпт как `ConversationBufferMemory`. LangChain `ConversationalRetrievalChain` комбинирует память и retrieved context.

**4. Потеря смысла на границах чанков**

*Проблема:* `RecursiveCharacterTextSplitter` может разрезать предложение или параграф.

*Решение:* Overlap 200 символов гарантирует перекрытие соседних чанков. Разделители в порядке приоритета: `["\n\n", "\n", ". ", " "]` — сначала делим по абзацам, затем по предложениям.

### 📈 Результат / Бизнес-ценность

- **MVP готов к демонстрации**: полный цикл от загрузки документа до ответа бота работает через Docker Compose одной командой.
- **Масштабируемость**: ChromaDB поддерживает миллионы векторов, Supabase — полноценный PostgreSQL с RLS.
- **Применимость**: корпоративная база знаний, HR-бот для онбординга, юридический ассистент, техподдержка — любой кейс с поиском по документам.
- **Потенциальный ROI**: снижение времени поиска информации сотрудниками с 15-30 минут до 10-30 секунд.
