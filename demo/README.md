# Демонстрация: сотрудник уточняет правила удалённой работы

Компания «Север», правила и файлы вымышлены. Сценарий показывает способ проверки RAG, а не внедрение у клиента.

1. Подготовьте окружение по корневому README, восстановите настройки, создайте таблицы в тестовой Supabase. Запустите ChromaDB и API на 8010. Используйте `CHROMA_COLLECTION_NAME=demo_sever_2026` и одинаковый `.env` для API и сборщика.
2. Выполните `python -m demo.run --live` через Python из `.venv`. Скрипт загружает два TXT через API, ждёт `done`, затем задаёт три вопроса из `questions.json`. Требуются сеть и платный доступ к embeddings/LLM.
3. Откройте `results.json`: вопросы, фактические ответы, источники и результаты поиска выдержки в локальном оригинале. Поле `expected_excerpt` находится отдельно в `questions.json`; скрипт никогда не выдаёт его за ответ модели.
4. Для первых двух вопросов проверьте: **до двух дней в неделю**, **согласовать с руководителем**, **не позднее 16:00 предыдущего рабочего дня**. Откройте `documents/sever_remote_work.txt`, раздел 1. `source` должен совпадать с именем этого файла; `excerpt` должен встречаться в тексте. Для TXT номер 1 не является физической страницей.
5. Для вопроса о компенсации интернета проверьте отсутствие придуманной суммы. Ожидается сообщение об отсутствии информации. Наличие найденных источников само по себе не подтверждает ответ. При выдуманной сумме зафиксируйте неуспех; не заменяйте ответ вручную.
6. Допишите ручную оценку в `VERIFICATION.md` с датой и именем файла прогона. Для сохранения истории используйте `--output demo/run-YYYYMMDD.json`.

Скрипт возвращает код 2 при отсутствующих настройках или ошибке. При успешных запросах результат остаётся `needs_human_review`: автоматическая проверка выдержки не оценивает смысл ответа. Предварительный режим без `--live` только парсит документы и проверяет настройки/доступность OpenAPI.

Повторная загрузка одноимённых документов вернёт 409. Скрипт не удаляет и не переиспользует старые данные автоматически. Для повторного опыта проверьте записи `documents` и удалите через API **только два учебных документа этого прогона**, используя ID из отчёта; затем повторите запуск. Не загружайте реальные корпоративные данные в демонстрационный стенд.

В этой итерации полноценный прогон остановлен отсутствием настроек. У всех трёх вопросов фактический ответ отсутствует. Файл с ожидаемыми фактами не является результатом LLM.
